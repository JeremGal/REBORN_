# Trade profiles

A profile is what ReBorn expects to find in **any** application of one trade, independent of which application. It is the memory that makes the method sharper over time: each new target of a trade is first checked against its profile, then the profile is enriched with what that target taught (new entities, new rules, new traps), **never with that target's code or content**.

## How a profile is used

1. Before investigating a new target, open its trade profile. Use the checklists as the first set of things to look for and the first `unknowns` to raise.
2. After investigating, add to the profile anything general the target revealed: an entity or rule common to the trade, a technology trap, a question that turned out to matter. Keep it generic, cite nothing proprietary.
3. If the target is a new trade, copy `_template.md` to `<trade>.md`.

## Each profile holds

- **Entities to expect** — the data objects almost every application of the trade has.
- **Rules to look for** — the computations, numbering, validations and workflows typical of the trade.
- **Screens that usually exist** — the windows a user of the trade will recognise.
- **First questions** — what to establish early, because the rest depends on it.
- **Technology notes** — what these applications are commonly built with, and the reading route that worked.
- **Migration notes** — fields that matter most to carry across when a customer switches.

## Profiles
